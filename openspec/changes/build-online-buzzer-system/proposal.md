# Proposal

## Why

課堂以紙本學習單與黑板搶答耗費時間，也難以同步各組進度、管理順位及回填答案。本專案從零建立線上搶答系統，將 Google Sheets 學習單、分組作答、可重算的公平順位與老師定案整合成可在本機展示的完整流程。

## What Changes

- 納入課程核心 C1–C9 與提案額外功能 E1–E6：老師／學生角色、活動代碼、組別加入、階段同步、題組、多題同輪、看板、可選倒數、公平排序、判錯遞補、寫回與 CSV。
- 採用 11/22 跨組規則。老師在建立活動時設定組數上限，學生以數字組號加入，既有組透過同組裝置或老師看板提供的 6 位數憑證驗證。學生可在準備中或結果階段離組，老師可刪除從未有效提交的組別。
- 老師控制權綁定建立活動的瀏覽器工作階段，每個老師工作階段同時只能有一個進行中活動。準備中可取消，取消後沒有寫回與 CSV。兩種排序模式皆可獨立設定 1～3600 秒倒數，匯入時自動選用單一工作表。
- 動態辨識單題與題組的表頭、合併題號及答案格；不依賴固定座標。混合範例辨識為 4 題、6 格，單題範例為 6 題、6 格。
- 每組每題每輪最多一次有效提交；學生於搶答期間只能取得自己組的作答狀況，關輪後公開本輪結果。
- 公平模式預設關閉，開輪時固定。開啟時依成功次數與提交先後逐題排序；關輪固定題序，判錯或撤銷判錯均從本輪基準重算整輪。
- 結果公布與定案分開：老師確認後鎖定，未被判錯者視為接受；定案後才能開下一輪或結束活動，歷史輪次不得改判。
- 老師手動預覽並寫回所有已定案勝者答案，保留其他格；寫回前檢查結構，失敗可重試且不改動活動結果。
- 伺服端及服務層使用 Python，頁面使用 HTML/CSS，搭配必要的原生 JavaScript 處理送出、輪詢與倒數。
- 本次只產生規劃 artifacts；實作須在後續 apply 才開始。
- 不納入進階答案圖表、預測盤、下注積分、成績連動、正式跨裝置部署、重啟恢復、自動批改、定案後改判或 XLSX 產品備援匯入。

## Capabilities

### New Capabilities

- `activity-session`: 老師與組別身分、活動建立、輪次生命週期、階段同步及存續範圍。
- `guided-notes-import`: Google Sheets 選取與授權、動態單題／題組解析、來源結構與答案格映射。
- `round-submission`: 多題提交、去重、截止、老師看板及依角色限制可見性。
- `ranking-review`: 速度與公平順位、判錯及撤銷、整輪重算、結果定案與成功次數。
- `result-export`: 定案結果預覽、原表寫回、結構保護、重試及 CSV。

### Modified Capabilities

無。專案目前只有 OpenSpec 初始化設定，沒有既有能力規格或應用程式碼。

## Impact

- 未來新增 Python Web 應用、獨立服務／領域邏輯、HTML 模板、CSS、原生 JavaScript、Google Sheets 轉接器及自動與人工驗證文件；本 change 不直接實作。
- 外部整合需要 Google OAuth、Picker 與 Sheets API；實際授權帳號及讀寫能力仍待實作前驗證，憑證不得進入版本控制。
- 對齊依據為「期末專題說明 (1).pdf」、「課堂搶答系統-SpecKit-組提案.pdf」及兩份 Excel 範例；採用 Explore 已確認的排序、重算、定案與寫回規則。附件中的 SpecKit 命令、分工與 Diagram First 指令不是本專案的執行指令。
- C1–C9、E1–E6、公平預設關閉、每輪一次、題組計一題與提前結束作為本版規劃基線。11/22 確認的十項跨組規則已納入本 change，其他對齊事項、助教題數口徑和 Google 存取驗證仍待追蹤。
