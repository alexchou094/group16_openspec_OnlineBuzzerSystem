# 作答、看板與審閱操作

本文件對應第 4、5 組新版三態逐筆審閱（2026-11-26）。啟動方式沿用根目錄 README；正式環境必須先由第 3 組匯入題目才能開輪。現有 BUZZER_DEMO 是明確開啟的測試模式，不能當作 Google 匯入驗收。

1. 老師建立活動並設定組數上限。學生首台裝置用活動代碼、1～N 組號加入；同組其他裝置還須輸入六位數憑證（保留前導零）。老師看板列出各組憑證；學生只能看到本組憑證。裝置失去身分時向老師索取原組憑證，勿誤建新組。
2. 準備中或結果階段可離組；只解除目前裝置身分，原提交與成功次數留在原組。老師可刪除從未有效提交的空組，刪除後所有舊裝置和舊憑證失效。曾提交後即使全部判錯也不能刪除。
3. 老師選尚未成功題、速度或公平模式，倒數留空由老師關輪，或填 1～3600 秒。開始後題目、模式與截止固定。學生依紙本題號任意順序作答，每題須一次填完所有子空格。
4. 每格最多 500 個 Unicode 碼點，中文及補充平面字元（例如 😀）各算一字；空白與換行也計入。輸入框顯示即時字數，允許多行。答案前後空白與換行原樣保存及顯示；全空白、超限、缺格、多格或非開放題整筆拒絕，不消耗機會。
5. 每組每題每輪只有第一筆有效答案。同組兩台競爭或重送會保留原答案、原時間和序號。尚未收到成功回應不能假設已送出；回應遺失時等狀態同步或重送確認。斷線顯示提示並自動重連；重新整理可恢復完整狀態。
6. 截止依伺服器取得活動鎖後的單調時鐘判定，恰等於截止也拒絕。前端倒數僅為提示。舊輪次提交不能帶到新輪。關輪前學生只看本組作答及已定案成功次數；老師看板顯示答案與「提交先後」，不提供暫估順位。
7. 關輪後先顯示「待審閱」，不自動認定最快者答對。老師按固定題序逐題審閱：速度模式按提交先後；公平模式先比該題處理時成功次數，同次數再比提交先後。後題顯示「等待前題審閱」，不預測勝者與順位。
8. 只有當前候選顯示「確認正確」及「判錯」。判錯後繼續下一候選，不須填原因；首筆確認正確就停止該題，題組任一格錯誤則整筆判錯。前面判錯者顯示「判錯 · 搶答失敗」，勝者顯示「正確 · 搶答成功」，勝者後面的答案僅顯示「搶答失敗」，不代表答對或答錯。題組成功只算一次。
9. 定案前可對已判定者「撤銷審閱」。確認對話框會提示受影響題號；撤銷會清除該題此位置以後與所有後題的判定，移除失效勝者並要求重審。原答案、時間、固定題序不變。公平模式的後題候選可能改變，仍須人工確認才會成為勝者。多分頁版本衝突時，重新檢視最新結果再操作。
10. 每題均找到首筆正確、全錯或無提交後，才顯示「確認定案」。勝者後未審閱答案不阻擋定案，也不會被視為正確。定案鎖定、重送不重複加分；之後才可下一輪或結束。全錯或無提交題可重開，成功題不可重開。

## 模組交接

- 第 3 組：呼叫 ActivityService.replace_questions，提供 SourceSnapshot 與 Question（穩定 id、數字題號、有序 Blank(label,target)）。只有準備中能替換；正式服務沒有自動補 fixture 或略過匯入的邏輯。
- 提交 API：POST /activities/{id}/rounds/{round}/submissions，body 僅含 question_id、answers。組別從 session 判定，不接受組別、時間或接收序號欄位。回應含 already_submitted 和自己組的不透明 submission id。
- 審閱 API：PATCH /activities/{id}/rounds/{round}/reviews/{submission}，body 為 `{"review_status":"CORRECT","expected_review_version":1}`；判錯用 INCORRECT，撤銷用 UNREVIEWED。過期、跳號、未審閱即撤銷或已定案回 409；舊版 rejected 欄位回 422。script 內容雜湊版本會讓新頁面載入新介面。
- 第 6 組：僅讀 finalized 輪次。results 含 winner_group_id、candidates（submission_id、rank、successes_before）、reason、status、current_submission_id；submissions 保留原文與 review_status。rejected 是由 INCORRECT 衍生的唯讀屬性，False 不代表答對。狀態 WAITING 的順位及處理時次數為 null；判錯 rank 為 null，其餘連續排序。cumulative_counts 是重算後累計，finalized_revision 每次新定案加一。使用 service.timestamp 將 received_at 轉 UTC。依 blanks 原順序映射 answers 至 target；CSV 十欄末欄應保存正確／判錯／未審閱。
- 活動鎖保護提交、關輪、審閱與定案。匯出應在鎖內複製定案快照，再於鎖外做外部 I/O。請勿直接修改歷史 results 或 submissions。

瀏覽器呈現使用 textContent，HTML/公式樣式答案仍為原始文字。公開輪次結果不含憑證；老師的私有組別區與學生自己的組別區仍可顯示相應憑證。

第 2 組新版空組自動釋放與刪組階段限制的既有缺口，見 [新版驗證紀錄](round-review-v2-verification.md)；人工操作請在準備中或結果階段由老師刪除空組。本次沒有修改第 2 組離組/刪組流程。

## 人工驗證建議

使用老師與至少兩組的獨立瀏覽器設定檔，同組第二台用另一設定檔及同組憑證。第一輪用兩題測速度，下一個活動用相同提交先後測公平：甲先送兩題、乙後送兩題，依序確認正確後應分別為甲贏兩題、甲乙各一題。公平輪撤銷題一正確後，題二須變回等待；題一改為甲錯乙對後，題二須先審甲，不能自動勝出。另以四組同題測錯、錯、對，第四組應只顯示搶答失敗。測試含空白換行的 500 字與 501 字、全錯重開、定案鎖定與離線恢復。這些是操作步驟，實際自動測試證據見新版紀錄；不代表已由其他組員人工驗收。
