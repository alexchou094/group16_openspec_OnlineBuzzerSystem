# 作答、看板與審閱操作

本文件對應第 4、5 組。啟動方式沿用根目錄 README；正式環境必須先由第 3 組匯入題目才能開輪。現有 BUZZER_DEMO 是明確開啟的測試模式，不能當作 Google 匯入驗收。

1. 老師建立活動並設定組數上限。學生首台裝置用活動代碼、1～N 組號加入；同組其他裝置還須輸入六位數憑證（保留前導零）。老師看板列出各組憑證；學生只能看到本組憑證。裝置失去身分時向老師索取原組憑證，勿誤建新組。
2. 準備中或結果階段可離組；只解除目前裝置身分，原提交與成功次數留在原組。老師可刪除從未有效提交的空組，刪除後所有舊裝置和舊憑證失效。曾提交後即使全部判錯也不能刪除。
3. 老師選尚未成功題、速度或公平模式，倒數留空由老師關輪，或填 1～3600 秒。開始後題目、模式與截止固定。學生依紙本題號任意順序作答，每題須一次填完所有子空格。
4. 每組每題每輪只有第一筆有效答案。空白、缺格、多格或非開放題不消耗機會。同組兩台競爭或重送會保留原答案、原時間和序號。尚未收到提交成功回應不能假設已送出；回應遺失時等待狀態同步或重送確認。同步中斷顯示提示並自動重連；重新整理可恢復完整狀態。
5. 截止依伺服器取得活動鎖後的單調時鐘判定，恰等於截止也拒絕。前端倒數僅為提示。舊輪次頁面不能把提交帶到新輪。關輪前學生無法查看他組進度，老師看板顯示答案及明確標示的暫估順位。
6. 關輪後所有組可查看完整提交、候選順位、判錯及勝者。題序按最早接受提交固定，無提交題置後。速度模式以接收先後排序；公平模式逐題按當時成功次數優先，同次數依接收先後。題組無論幾格只算一次。
7. 老師可對任一候選「判錯」或「撤銷判錯」，題組整筆排除。答案原文不刪除。每次改判從歷史基準重算整輪，其他題的勝者可能改變；畫面列出「結果更新」題號及勝出理由。多分頁操作碰到版本過期時，重新檢視最新結果後操作。
8. 確認定案代表接受所有未判錯答案。定案不可改判，重送確認不重複加分；定案後才可下一輪或結束。全錯或無提交題可下輪重開，已成功題不可重開。結束仍保留歷史結果。

## 模組交接

- 第 3 組：呼叫 ActivityService.replace_questions，提供 SourceSnapshot 與 Question（穩定 id、數字題號、有序 Blank(label,target)）。只有準備中能替換；正式服務沒有自動補 fixture 或略過匯入的邏輯。
- 提交 API：POST /activities/{id}/rounds/{round}/submissions，body 僅含 question_id、answers。組別從 session 判定，不接受組別、時間或接收序號欄位。回應含 already_submitted 和自己組的不透明 submission id。
- 審閱 API：PATCH /activities/{id}/rounds/{round}/reviews/{submission}，body 為 rejected 與 expected_review_version。過期回 409。
- 第 6 組：僅讀 finalized 輪次。results 每題含 winner_group_id、candidates（submission_id、rank、successes_before）、reason；submissions 保留原文及 rejected。cumulative_counts 為本輪重算後累計；活動 finalized_revision 每次新定案加一。使用服務 timestamp 將單調 received_at 轉為 UTC。依 blanks 原順序映射 answers 至 target，不以子格重複計分。
- 活動鎖保護提交、關輪、審閱與定案。匯出應在鎖內複製定案快照，再於鎖外做外部 I/O。請勿直接修改歷史 results 或 submissions。

瀏覽器呈現使用 textContent，HTML/公式樣式答案仍為原始文字。公開輪次結果不含憑證；老師的私有組別區與學生自己的組別區仍可顯示相應憑證。
