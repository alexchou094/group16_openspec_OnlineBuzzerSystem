# spec01 人工驗收紀錄

範圍為 `activity-session`。案例 01–09 的結果依使用者回報記錄。案例 10 保留修正前的使用者觀察、人工重測步驟及修正後的自動驗證結果。

## 測試環境

依 [README](../../../README.md) 的本機啟動步驟開啟示範模式。測試使用同一服務網址，老師 T、學生 A、學生 B 分別使用獨立的瀏覽器設定檔。案例 03 另用設定檔 C 模擬同組第二台裝置。

## 案例 01–09

下表保留原操作和預期結果。使用者回報九項均通過，個別量測值與測試附件未提供。

| 編號 | 操作 | 預期結果 | 使用者回報 |
| --- | --- | --- | --- |
| 01 建立活動 | T 試空白、`0`、`1.5`，再輸入 `2` 建立。用同設定檔的第二分頁開啟活動，並從首頁試建第二個活動。 | 無效輸入被拒絕。建立後顯示代碼及「準備中」。第二分頁有控制權，同時只能有一個進行中活動。 | 通過 |
| 02 組號與權限 | A 試錯誤代碼和空白、`0`、`1.5`、`3` 的組號。再讓 A 加入第 1 組、B 加入第 2 組，並用 A 的設定檔開啟活動網址。 | 無效資料被拒絕，組號 `1`、`2` 可加入。A 只看到本組身分與憑證，畫面沒有老師專用按鈕。 | 通過 |
| 03 同組多裝置 | C 依序用空白、錯誤、正確憑證嘗試加入第 1 組。A、C 重新整理後離組，A 再用老師提供的憑證加入。 | 只有正確憑證可加入既有組別。重新整理可恢復身分，老師提供的憑證可供離組後重新加入。 | 通過 |
| 04 刪除空組 | 記下第 2 組憑證，T 刪除第 2 組。B 留在原活動頁，之後回首頁，先用舊憑證再留空嘗試加入。 | B 原頁失去權限，舊憑證失效；留空重建同一組號後取得新憑證。 | 通過 |
| 05 開輪與同步 | T 確認未載入題目前無法開輪。載入示範題後選第 1、3 題，速度模式、無倒數。觀察 A、B，再由 T 手動關輪。 | 三個畫面顯示相同開放題目。搶答中沒有離組或取消按鈕。關輪後三個畫面在兩秒內更新為「本輪結果」。 | 通過 |
| 06 定案與倒數 | 確認第一輪暫定，再由 T 定案。下一輪選公平模式，分別試 `0`、`3601`、`1.5` 秒，最後用 `1` 秒開輪。 | 暫定時不能開下一輪或結束。無效秒數被拒絕。倒數到期自動關輪，仍需老師定案。 | 通過 |

| 08 取消與重連 | T 建立新活動，A 加入。將 A 的開發者工具 Network 切到 `Offline`，T 取消活動，再讓 A 恢復連線。 | A 先顯示「同步中斷」，重連後自動更新為「已取消」。原代碼無法加入，T 可再建立活動。 | 通過 |
| 09 伺服器重啟 | T 建立活動並保留活動頁。停止伺服器後以相同指令重啟。 | 舊頁顯示「活動已失效或不存在」，回首頁可重新建立活動。 | 通過 |

## 案例 10 關閉瀏覽器後重開

**使用者觀察**：老師、學生關閉視窗再開後皆未恢復原身分，原活動及學生組號仍保留。瀏覽器版本、關閉範圍與原頁提示待重測記錄。

1. 伺服器持續運作。T 建立組數上限為 `1` 的活動，A 加入第 `1` 組。記下活動網址與開啟的瀏覽器設定檔。備妥仍可查看活動狀態的另一個設定檔，例如讓 B 以憑證加入同組。
2. **學生重測**：關閉 A 的瀏覽器視窗，透過原設定檔開回首頁與原活動頁。記錄是否有回到活動的入口、原頁是否識別第 `1` 組，以及 T 看板是否仍顯示該組。用未加入的設定檔嘗試以空白憑證加入第 `1` 組，記錄結果。
3. **老師重測**：保留 T 的活動及 B 的頁面。關閉 T 的瀏覽器視窗，透過原設定檔開回首頁與原活動頁。記錄首頁是否有回到活動的入口、原頁是否仍有老師操作權，以及 B 是否仍看得到原活動。
4. 如果單一視窗關閉後仍可恢復身分，再關閉該設定檔的所有視窗後重測。分別記錄瀏覽器與版本、關閉的是單一視窗或全部視窗、是否使用無痕模式、是否啟用關閉時清除 Cookie，以及畫面的實際提示。

**預期行為**：伺服器持續運作時，老師與學生各自用保留網站 Cookie 的原設定檔重開瀏覽器，開啟原活動網址即可恢復老師控制權或原組別身分。

**自動驗證**：在 Windows 使用 Chrome 和兩個獨立設定檔重開瀏覽器，學生重新取得第 1 組身分，老師可以取消原活動，學生隨後看到「已取消」。另以 HTTP 測試確認新的伺服器實例會拒絕舊活動的狀態請求。
